# BilldDesk 私有 Android 客户端

新增的原生 Java 客户端，版本 `0.1.27`，包名 `art.aduning.billddesk`。通过现有 BilldDesk 服务端的 REST、Socket.IO 信令和 WebRTC 协议连接网页/桌面客户端，不依赖缺失的 Flutter 源码。

## 功能与使用

- 私有服务器设置：默认 `https://desk.aduning.art`，可修改 HTTPS 地址和 TURN 中继配置。
- 设备代码和连接密码：自动注册、保存身份、复制连接信息、更换密码。
- 手机作为被控端：用户开启整屏共享，每个远程连接都需在手机确认。前台通知和首页均可停止共享。
- 无障碍远程触控：点击、拖动、长按、滚动、返回/主页/任务、通知栏/快捷设置/收起系统栏，以及编辑输入框中的文字。未开启无障碍时仍可共享画面。
- 网页和 Mac 控制安卓时，右上角显示系统操作按钮；键盘快捷键为 Alt+Shift 加 B（返回）、H（桌面）、R（多任务）、N（通知栏）、S（快捷设置）、C（收起），Mac 对应 Option+Shift。观看模式、通道未连接或编辑本地输入框时不执行这些快捷动作。通知和控制中心可能被手机系统的屏幕共享保护排除，按钮打开成功不代表远程视频可见。
- 手机作为控制端：连接成功后自动进入横屏全屏，隐藏首页和系统栏；可以切换竖屏、返回窗口模式，触控、发送文字和断开连接。切换方向不会重新建立连接。
- 横屏全屏时，窗口、竖屏、画质、复位、文字、断开按钮放在右侧；竖屏和窗口模式放在底部。视频保持原始比例，完整显示桌面，触控坐标随布局换算。
- 支持双指张合缩放（100%–400%）、双指拖动平移；放大后单指滑动平移本地画面，100% 时单指拖动只移动远端鼠标光标，抬手不点击。轻点操作远端，长按后再拖动才用于文本选择或远端内容拖拽；开始移动光标后即取消长按判定，持续慢拖也不会转成鼠标按住拖拽。转入双指手势时释放已发送的鼠标按键，抬起一指后可继续单指平移，需全部抬起才恢复远端控制；本地平移和缩放不发送鼠标事件。缩放提示位于右上角。“复位”恢复完整画面，断开/重新连接后恢复100%。输入弹窗、方向和窗口变化时保留缩放并限制平移范围，点击坐标按缩放和偏移反算。
- 连接电脑默认目标 1440P、60 帧/秒、最高 12000 kbps，使用文字内容提示。“画质”可分别选择 720/1080/1440/2160P、30/60 帧、6/12/20/30 Mbps，立即应用到当前连接并记住设置；弹窗持续更新实际收到的尺寸和帧率，帧率从第一帧开始统计。
- 控制通道打开后再次发送画面参数，确保电脑编码器实际应用码率。Mac 录屏初始化允许最高 60 帧，修复原先采集源锁在 30 帧的问题。实际分辨率、帧率和码率仍受对端采集、网络和编码器影响；2160P 指画面高度，宽度随电脑屏幕比例变化，不一定为 3840。高码率是上限，静止桌面不需要持续跑满。
- 记住电脑：连接弹窗默认勾选“记住设备号和密码”，通过对端验证并收到视频轨道后保存。之后在“已保存设备”点连接即可重连，支持修改密码、忘记设备；重启 App 后仍会恢复最近的设备号。

Android 8.0 及以上；当前安装包仅包含 `arm64-v8a`。不包含文件传输、系统声音传输、开机自启或无人值守控制。系统保护的界面、密码框和禁止截图的应用可能限制共享或输入；锁屏/结束屏幕共享会停止传输。

被控手机：先开启“远程触控权限”，再开启“屏幕共享”，将代码和密码交给对方，并确认连接请求。控制端：输入对方的代码和密码，等待对方允许。控制电脑时，电脑客户端需要系统允许屏幕录制和输入控制。

保存的连接密码通过 Android Keystore 的设备密钥进行 AES-GCM 加密，按服务器与设备号隔离；保存记录不进行云同步或迁移备份，连接仍需经过私有服务器验证密码。电脑更换临时密码后，需要在已保存设备中点“修改”并连接一次。

## 构建

使用 JDK 17 及以上、Android SDK 35；已固定 Gradle 8.14.5、AGP 8.13.2 和依赖版本。Gradle Wrapper 包含官方发行包 SHA-256 校验。

在此目录创建被 Git 忽略的 `local.properties`：

```properties
sdk.dir=/absolute/path/to/Android/sdk
```

服务配置读取项目根目录被忽略的 `.env.production.local`，字段与网页/桌面部署一致：`VITE_WEB_DESK_URL`、`VITE_COTURN_URL`、`VITE_COTURN_USERNAME`、`VITE_COTURN_CREDENTIAL`。缺少凭证时仍可尝试直连，但跨网络的 TURN 中继不可用。客户端中的中继凭证可被提取，不能用作管理密钥。

发布签名读取此目录被忽略的 `signing.local.properties`：

```properties
storeFile=/absolute/private/path/android-release.jks
storePassword=YOUR_STORE_PASSWORD
keyAlias=billddesk
keyPassword=YOUR_KEY_PASSWORD
```

保护并备份签名密钥，后续覆盖升级须使用同一签名。签名密钥和密码不应提交或放入下载目录。未提供签名配置时 release APK 未签名，不能直接安装。

```bash
./gradlew :app:assembleRelease :app:lintRelease
adb -s DEVICE_SERIAL install -r app/build/outputs/apk/release/app-release.apk
```

输出 `app/build/outputs/apk/release/app-release.apk`。当前本地副本为根目录 `android-release/0.1.27/BilldDesk-android-0.1.27-arm64.apk`；`0.1.27` 已覆盖安装并实测，尚未上传下载服务器。已发布的在线下载仍为 `https://desk.aduning.art/downloads/BilldDesk-android-0.1.4-arm64.apk`。

手机被控端在有人连接且屏幕静止时，每半秒尝试重送当前采集纹理，使用新时间戳进入编码链路，避免详情退出动画的最终帧被丢弃后一直显示残影。停止共享时取消补帧；动态画面仍按原采集和帧率上限处理。补帧不保证所有网络条件下半秒内到达，也不代表静态页面需要持续 60 fps。`0.1.27` 另将硬件编码器的帧率预算固定为用户选择的采集上限，避免静止时估算降到 1–2 fps 后恢复动画产生超大帧；将屏幕共享 ALR 的发送排队目标从默认 2875 ms 调整为 100 ms，保留原码率控制和探测参数。两端原速录屏与发送统计确认详情过渡明显改善；高码率长静止后的大帧和编码掉帧仍有波动，不能据此保证全程 60 fps，见 [编码与发送排队复测记录](../ops/remote-encoder-pacing-validation-20261007.md)。

## 协议与权限

信令对应 `src/hooks/use-websocket.ts`、`src/hooks/webrtc/remoteDesk.ts`；控制消息对应 `billdDeskBehavior`，并增加 Android 间的 `androidAction` 导航消息。SDP 和 ICE 仅接受当前授权会话的发送者。共享和无障碍需用户明确开启；无障碍服务不采集或上传界面事件，只在已确认的共享连接中执行控制消息。身份和服务器配置禁止云备份/设备迁移；日志不记录连接密码、SDP 或 TURN 凭证。

依赖：WebRTC Android SDK `150.7871.01`（BSD）、Socket.IO Java client `2.1.2`（MIT）、OkHttp `4.12.0`（Apache 2.0），以及各自的传递依赖。依赖许可以其上游仓库和发布包为准。
