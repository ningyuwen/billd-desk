# BilldDesk 小程序远控 Mac：开发与验收方案

编写日期：2026-10-08。本文是后续开发任务书；计划中的功能和验收项不代表已经实现或通过。

## 1. 用户目标与执行约定

- 独立微信小程序测试号，供两三个人自用、轮流连接 Mac；不接入青柠遥控，不以公开发布为本轮目标。
- 复用现有 Mac App、服务器和 WSS 中继，继续采用 JPEG + Canvas，不引入按月收费的音视频 SDK。
- 用户计划**新开一个 Codex 会话，并让多个子 Agent 同时开发**。新会话主 Agent 应按第 7 节组织并行工作；本次编写文档不启动开发或子 Agent。
- 项目根目录 `AGENTS.md` 是实施依据。应用代码修改必须完成源码、编译、对应端部署和运行验证；设备或权限缺失要明确记录。
- 本文不自动授权 Git 提交、推送、合并或公开发布。客户端覆盖安装遵循项目持续授权；新增线上服务变更按用户对该次操作的明确指令执行，不把历史一次部署许可当作永久授权。

最终体验流程：打开 Mac 共享 → 手机粘贴或扫码配对 → Mac 允许 → 查看并放大画面 → 点击、输入、拖动 → 任一端主动断开。

### 2.2 当前能力

- Mac 主屏幕，最大 1280×720、最多 5 FPS，无音频。
- 随机连接码与临时密码，Mac 手动允许，同一会话只允许一个控制端，会话两小时失效。

- 代码已有单击、长按右键、滚动、文本和 Enter / Backspace / Esc；Mac 可复制整段邀请，手机可粘贴填入。

- 点击、右键、滚动、输入和按键尚未逐项真机验收；横竖屏、弱网、后台与重连仍待验收。

## 4. 详细开发方案

### 4.1 M0：连接、权限与基础操作

1. 将状态拆成未连接、连接中、等待 Mac 允许、等待首帧、已连接、画面暂停、断开中、已断开。禁止只用一段提示文字作为内部状态。
2. 分别处理连接信息错误、Mac 不在线、占用、拒绝、批准超时、录屏失败、首帧超时、帧更新超时、输入权限不足、协议不兼容和网络断开。
3. 批准计时从等待批准开始；首帧计时从批准成功开始。超时后释放本轮资源，不能影响下一轮连接。具体时限沿用现有值起步，集中配置并在验收记录注明。
4. Mac 开始共享前检查录屏权限；允许控制前检查辅助功能权限。缺少权限显示具体设置路径，授权后重试，不循环弹窗或抢前台。
5. 新连接使用独立会话标识；迟到消息、异步解码和旧连接回调不能修改新会话。开始断开后立即停止接受输入。
6. 任一端断开、拒绝、到期、手机切后台或 Mac 退出，统一清理计时器、帧缓存、临时文件、捕获流和原生输入授权。
7. 保留整段粘贴；连接后及断开时清除临时密码。Mac 的连接状态与主动断开按钮在固定 800×500 窗口中滚动可达。

权限实现参考：[Electron systemPreferences 官方文档](https://github.com/electron/electron/blob/main/docs/api/system-preferences.md)。实施时核对项目 Electron 版本，不用新版文档推定旧版本能力。

### 4.2 M1：画面查看、缩放与坐标

- 进入展开查看模式后，画面占满小程序可用区域，工具栏可收起；微信胶囊与安全区域保留可操作空间。
- 横竖屏使用实际可用窗口尺寸重算，不写死手机尺寸；先确认当前基础库和真实测试号支持的方向配置。
- 双指捏合缩放：以适配完整画面的比例为 1 倍，范围 1～4 倍，尽量保持手势中心对应的桌面位置稳定。
- 双指平移查看区域；限制边界，始终能回到画面。“适应屏幕”恢复居中、完整显示。
- 单指点按映射到 Mac；黑边、工具栏、双指操作不发送点击。
- 统一坐标转换：触点减去画布布局偏移，再逆向应用平移与缩放，最后转换为远端屏幕归一化坐标；设备像素比仅用于渲染，避免重复参与点击映射。
- 屏幕方向、键盘显隐或画布重建后，重绘当前有效帧；每次解码仍使用唯一文件名，保留旧缓存问题的回归覆盖。

### 4.3 M2：输入与手势

| 模式／手势 | 行为 |
| --- | --- |
| 直接触控单指点按 | 点击对应 Mac 位置 |
| 直接触控长按后松开 | 右键；长按期间取消普通点击 |
| 直接触控双指捏合／移动 | 缩放／平移手机查看区域，不控制鼠标 |
| 触控板单指移动／轻点／双轻点 | 相对移动指针／单击／双击 |
| 触控板双指上下移动 | 远程滚动，抑制单击 |
| 拖动模式 | 明确显示状态，按下鼠标 → 移动 → 松开鼠标；与查看区域平移分开 |

- 双击不能额外执行一次单击加一次双击；手势识别集中管理，移动阈值与长按阈值可调整。
- 补齐 `touchcancel`、离开画布、多指切换、切后台和断网时的取消路径。
- 文本保持完整 Unicode，支持中文、英文、换行、常用符号，继续限制单次长度；发送中断开后不能继续输入。
- 首批快捷键：`⌘C`、`⌘V`、`⌘A`、`⌘Z`、`⌘⇧Z`、`⌘Tab`、Tab、方向键，以及现有 Enter / Backspace / Esc。仅允许明确列出的组合，不接收任意系统命令。
- Mac 按会话记录按住的鼠标和按键；结束、超时、取消、权限异常均释放。释放指令不能被普通移动队列挤掉；持有输入增加失联保护。
- 输入失败、被拒绝或队列繁忙需要返回结果；文字发送和快捷键显示结果，鼠标移动无需每个事件弹提示。批量输入不在日志中记录文字内容。

### 4.4 M3：扫码配对与再次连接

- Mac 显示临时配对二维码与有效期，小程序首页增加扫码入口；保留复制和粘贴。
- 优先使用受版本与长度限制的邀请载荷，沿用已有 WSS、连接码、临时密码校验；显示前确认当前扫码 API 能读这种载荷，先做真实手机最小验证。
- 扫码只填写并发起配对，不绕过 Mac 允许。二维码包含临时凭证，应按密码处理，不保存到仓库、日志或公开图片。
- 停止共享／会话到期后旧邀请无效；刷新邀请须明确使旧凭证失效，先结束活动控制会话或禁止活动中刷新，不能悄悄撤销正在操作的用户。
- 仅保存设备昵称、中继地址和画质偏好，不保存长期可复用的临时密码。提供删除记录入口。
- 暂不实现无人值守或自动重连批准；再次连接仍由 Mac 确认。
- 配对二维码用于连接 Mac；开发者工具预览二维码用于打开开发版本，二者界面文案明确区分。测试号的预览使用限制需真实确认，不能承诺配对码能替代预览码。

### 4.5 M4：画质、弱网和可观测性

- 初始候选档位：省流 960×540 / 3 FPS、均衡 1280×720 / 5 FPS、清晰 1280×720 / 5 FPS 且提高 JPEG 质量。都是最大外框，保持实际屏幕比例，不放大低分辨率源；JPEG 参数经实测确定，清晰档仍受单帧上限约束。
- 首轮最高 5 FPS、单帧上限 560 KB，最多一帧等待显示 ACK；不为追求帧率取消背压。
- 弱网时降低质量或帧率，连续稳定后逐步恢复，增加冷却时间避免频繁跳档；手动档位是允许范围的上限。
- 显示或调试面板记录实际绘制 FPS、最近画面年龄、帧确认往返耗时、收发字节数。区分帧 ACK 耗时与纯网络 RTT，不把不同指标混称延迟。
- 提议连续 3 秒未绘制新帧进入画面暂停状态并禁用新输入；阈值集中配置，经真机测量调整。新鲜帧恢复后才重新开放输入。
- 重连由用户明确触发，失败重试有节流，不产生请求风暴。Mac 确认规则不因网络恢复而绕过。
- 用固定场景测量流量：静态桌面、窗口移动、文字编辑各 10 分钟。记录画质、网络及统计口径，再决定是否需要扩容或改变传输方案。

## 5. 协议与模块边界

主 Agent 在并行开发前写定 `ops/miniprogram/protocol-v2.md`，至少包含：

1. 版本／能力协商；不支持的功能在界面禁用并解释，不能发送后静默失败。新旧组合通过兼容模式或明确升级提示处理。
2. 状态事件与错误码，连接、请求和输入的关联标识，终止原因。
3. 原有输入兼容范围；新增双击、鼠标按下／抬起、相对移动或其转换方式、组合键的结构与校验。
4. 输入序号、结果确认、超时和重复消息处理。离散操作不因重试重复执行；高频移动可合并，释放和取消优先。
5. 画质能力与档位协商，帧序号、ACK、大小限制和缓存清理约束。
6. 邀请载荷版本、有效期、刷新与失效行为。真实凭证不出现在示例中。

先保留现有消息可用，再按能力开启新增功能。中继只能转发经校验的允许指令；Mac 原生层仍校验会话、参数和授权，不把中继校验当作唯一边界。中继继续不落盘画面、密码或输入；当前 TLS 链路没有应用层端到端加密，不扩大对不可信服务器的使用范围。

## 7. 新会话的多 Agent 并行安排

### 7.1 组织方式

建议**一个主 Agent + 三个子 Agent**。主 Agent 负责协议、文件归属、页面最终集成、构建安装、真机联调和验收记录；子 Agent 在同一新会话内执行，不另建多个用户会话。

| 角色 | 独占修改范围 | 主要任务 | 交付接口 |
| --- | --- | --- | --- |
| 子 Agent A：画面与手势 | `mini-program/lib/geometry.js`、新增 `viewer-renderer.js` / `viewer-gestures.js`、对应独立测试文件 | M1、两种操作模式的手势识别与坐标、画面缓存清理 | 画布初始化／重绘／销毁接口，语义化手势事件，状态回调 |
| 子 Agent B：输入与中继 | `electron-main/mini-control.ts`、`mini-relay/server.mjs`、`test/mini-control.test.mjs`、`mini-relay/test.mjs` | M2 原生输入、协议校验、输入结果、取消释放、能力协商 | 主 Agent 冻结的协议实现、原生 IPC 结果与测试 |
| 子 Agent C：Mac 主机与配对 | `src/views/remote/miniProgramHost.vue`、新增邀请／画质模块、对应独立测试文件 | M0 Mac 状态与权限、M3 二维码、M4 捕获画质和统计、连接输入结果转发 | Mac 协议接入、扫码载荷解码模块与候选参数 |
| 主 Agent：集成与验收 | `mini-program/pages/remote/index.*`、`app.json`、连接模块、现有 `mini-program/test.cjs`、共享入口／配置／锁文件、文档 | 手机状态、扫码页面、模块接入、里程碑验收与部署 | 可运行完整链路与可核验记录 |

模块名是建议，主 Agent 先确定导出接口与依赖方向再启动。子 Agent A 负责手势识别，主 Agent 把语义事件映射为协议；子 Agent C 的扫码解码模块由主 Agent接入页面。需要更改他人负责文件时先协商，不直接跨范围修改。

### 7.2 并行顺序

1. 主 Agent 核对基线与设备，运行现有检查，冻结协议和模块接口。
2. A 开发画面／坐标；B 开发输入／中继；C 开发 Mac 状态／配对／画质。三者可以同时进行。
3. 主 Agent 先集成 M0、M1，B 的新输入在能力声明就绪前不启用。
4. B 与 C 对齐原生输入结果和中继协议；主 Agent接入 M2 并真机验收。
5. 接入配对和画质，执行兼容检查与完整回归。
6. 子 Agent 报告改动、检查结果和未覆盖项；主 Agent独立核对后汇总，不能直接把子 Agent 的“完成”当作实机通过。

### 7.3 防冲突与共享资源规则

- 共享工作目录时严格按文件归属写入；不使用 `git add .`、重置、切换分支或批量格式化清理他人工作。
- `index.*`、共享协议、包配置、锁文件和现有小程序集成测试由主 Agent统一修改。子 Agent 新测试使用独立文件，主 Agent明确纳入测试命令。
- 依赖新增先报给主 Agent，再由主 Agent统一安装和审查；避免三方同时改锁文件。
- **Mac 打包、覆盖安装、开发者工具预览、真实共享会话和线上部署串行执行，由主 Agent统一操作。** 子 Agent不能各自争抢窗口、重启 App 或同时生成预览。
- Mac 的“允许”与系统权限由用户完成，不把权限障碍绕成虚假的通过结果。测试时只有一个控制端，模拟器退出后再交给手机。
- 子 Agent 可运行不争用资源的独立单元测试；公网测试先确认不影响用户当前会话。
- 每次接口变动由主 Agent更新契约并通知相关 Agent。阻塞时继续独立模块，不通过临时不兼容消息绕过。

## 8. 验收环境与记录要求

### 8.1 环境

## 10. 自动化、构建与部署验收

### 10.1 自动化

先运行现有回归：

```bash
node --test mini-relay/test.mjs mini-program/test.cjs test/mini-control.test.mjs
```

新增测试至少覆盖：逆坐标转换与边界、手势取消、状态转换和旧会话隔离、路径缓存与图片清理、指令允许范围、按住输入释放、序号重复、能力不兼容、邀请失效及弱网背压。主 Agent将新增独立测试文件显式纳入统一命令，避免“文件存在但没运行”。

受影响 Vue / Electron 文件执行 ESLint 和项目类型检查。测试应验证行为与故障边界，不仅复述实现；自动化通过后仍执行第 9 节真机操作。

### 10.2 Mac 构建与安装

先阅读 `ops/README.md`，确认当前私有配置、原签名身份和架构。当前 ARM64 验证入口：

```bash
VITE_APP_RELEASE_PROJECT_ISWEB=false npm exec --yes --package=pnpm@9.15.9 -- pnpm exec vite build
CSC_IDENTITY_AUTO_DISCOVERY=false npm exec --yes --package=pnpm@9.15.9 -- pnpm exec electron-builder --mac --arm64 --config electron-builder.private.json5 --publish never
```

核对产物签名和哈希后覆盖安装，完全退出旧进程，通过 Finder、Dock 或 LaunchServices 启动安装版，再验证录屏与输入。不能以终端直接启动二进制的成功结果替代 App 本身 TCC 授权验收。不运行会自动改版本或创建提交的打包入口。

### 10.3 小程序与中继

- 开发者工具编译、检查代码包、生成本次预览码；手机重新扫码，记录当前代码标识。二维码过期按工具实际状态刷新，不保证固定有效时长。
- 保留 `urlCheck: true`。使用现有 WSS 直连，不引入 `web-view` 时不新增业务域名；若后续增加 HTTPS 接口，再按实际接口配置合法域名。
- 中继协议修改先跑本地测试；线上变更前准备确切部署差异、备份、兼容顺序和回退步骤，并按项目规则取得该次明确授权。
- 线上部署执行健康检查、公网合成帧测试、真实 Mac 与手机操作；合成帧仅证明协议链路。若需要重启中继，提前结束活动控制会话。
- 新旧版本通过能力协商安全降级或清楚提示；逐端更新后再开启新功能。回退要覆盖中继代码、客户端协议组合与配置，不更换签名或删除用户数据。
