原项目目录：/Users/bytedance/WebstormProjects/billd-desk

三、必须迁移的 Mac 签名身份

原目录：
  /Users/bytedance/.config/billd-desk/signing/
目标目录：
  新 Mac 的 ~/.config/billd-desk/signing/

迁移整个目录，核心文件包括：
  billd-desk.keychain-db   专用签名钥匙串，包含签名身份
  identity.p12            加密的证书及私钥备份
  certificate.pem         证书
  keychain-password       钥匙串及 P12 密码
  identity.json           签名指纹和文件路径

当前签名信息：
  证书名称：BilldDesk Local Code Signing
  应用标识：com.billddesk.app
  证书 SHA-1：8D167221FED1C3D3B775D052BD7671E79FC348A6
  类型：固定本地自签名证书；未使用 Apple Developer ID，未做 Apple 公证。

迁移注意事项：
  1. 不要在空目录先运行 setup-mac-local-signing.py，它会生成新证书。
  2. 保留原指纹和私钥，不重新生成证书，不回退 ad-hoc 临时签名。
  3. identity.json 中 keychain、passwordFile 当前是旧电脑的绝对路径。
     新电脑用户名或用户目录不同时，必须改为新电脑上的实际路径。
  4. 目录权限为 0700，核心文件权限为 0600。
  5. 不提交这些文件，不放入公开下载目录，不随安装包分发。

复制完成后，可在新 Mac 执行以下命令更新路径，保留原身份：

python3 - <<'PY'
import json
from pathlib import Path
root = Path.home() / '.config/billd-desk/signing'
config = root / 'identity.json'
data = json.loads(config.read_text())
expected = '8D167221FED1C3D3B775D052BD7671E79FC348A6'
if str(data.get('identity', '')).upper() != expected:
    raise SystemExit('证书指纹不匹配，请检查迁移来源。')
for name in ['billd-desk.keychain-db', 'identity.p12', 'certificate.pem', 'keychain-password']:
    if not (root / name).is_file():
        raise SystemExit('缺少签名文件：' + name)
data['keychain'] = str(root / 'billd-desk.keychain-db')
data['passwordFile'] = str(root / 'keychain-password')
config.write_text(json.dumps(data, indent=2) + '\n')
root.chmod(0o700)
for name in ['billd-desk.keychain-db', 'identity.p12', 'certificate.pem', 'keychain-password', 'identity.json']:
    (root / name).chmod(0o600)
print('原签名身份保留，路径已更新。')
PY

签名脚本会读取密码并解锁专用钥匙串。
若新 Mac 无法使用迁移后的钥匙串，应从原 identity.p12 恢复同一身份，
并确认 codesign 对私钥的访问权限；不要通过生成新证书绕过问题。
本文未验证钥匙串在新 Mac 上的可用性。

四、桌面开发依赖与构建

需要安装：
  Node.js：原机为 v26.2.0，项目未固定 Node 版本，可作为环境复现参考。
  pnpm：项目现有构建流程使用 9.15.9。
  Xcode Command Line Tools：可通过 xcode-select --install 安装。
  Python 3：用于签名配置维护脚本。

原机依赖版本参考，以 pnpm-lock.yaml 为实际安装依据：
  Electron 33.2.1
  electron-builder 25.1.8
  @nut-tree-fork/nut-js 4.2.2

在项目根目录安装依赖：
  npm exec --yes --package=pnpm@9.15.9 -- pnpm install --frozen-lockfile --registry=https://registry.npmjs.org

桌面端安装不要添加 --ignore-scripts，Electron 有 postinstall 安装脚本。
.npmrc 的 hoist 配置已随仓库提供，不需要手动重建。
不能直接复制不同架构电脑的 node_modules。

本地启动：
  npm exec --yes --package=pnpm@9.15.9 -- pnpm run dev

Apple 芯片 Mac 的正式验证构建：
  VITE_APP_RELEASE_PROJECT_ISWEB=false npm exec --yes --package=pnpm@9.15.9 -- pnpm exec vite build
  CSC_IDENTITY_AUTO_DISCOVERY=false npm exec --yes --package=pnpm@9.15.9 -- pnpm exec electron-builder --mac --arm64 --config electron-builder.private.json5 --publish never

产物位置：electron-release/<package.json 中的版本>/
Intel Mac 须使用相应架构配置并重新验证，不能直接照搬 --arm64。
不要直接运行带 standard-version 的 build:mac 等脚本，避免意外修改版本或提交。
桌面和网页构建会覆盖同一个 dist/，部署前须确认构建类型。

五、如果还要开发和打包 Android

需要安装：
  JDK 17 及以上
  Android SDK Platform 35、所需 Build Tools、Platform Tools（含 adb）
  接受对应 Android SDK 许可

仓库已固定：
  Gradle 8.14.5，由 ./gradlew 使用和下载
  Android Gradle Plugin 8.13.2
  当前 Android 包名 art.aduning.billddesk
  当前 APK 架构 arm64-v8a

必须迁移：
  原项目/android-client/signing.local.properties
  /Users/bytedance/.codex/private/billd-desk/android-release.jks
  /Users/bytedance/.codex/private/billd-desk/android-keystore-password

建议私密迁移整个 ~/.codex/private/billd-desk/ 目录。
signing.local.properties 中的密码和 keyAlias 保留原值，
storeFile 改为新 Mac 上 android-release.jks 的实际绝对路径。
后续覆盖升级现有手机 APK 必须使用原发布密钥。
缺少签名配置时 release APK 未签名，不能直接安装。

新项目/android-client/local.properties 应按新电脑重新填写：
  sdk.dir=/新电脑的实际绝对路径/Android/sdk

原机路径仅供参考：/Users/bytedance/Library/Android/sdk
不要把旧电脑的用户名和 SDK 路径原样复制到不同用户目录。

构建及安装，在 android-client/ 下执行：
  ./gradlew :app:assembleRelease :app:lintRelease
  adb devices -l
  adb -s <本次确认的设备序列号> install -r app/build/outputs/apk/release/app-release.apk

手机需确认新 Mac 的 USB 调试授权。
覆盖安装保留数据，不卸载、不清空手机已有设备和密码记录。

七、应用历史数据与系统权限

原 Mac 应用数据目录：
  /Users/bytedance/Library/Application Support/BilldDesk/

开发环境迁移无需复制此目录。
如确实需要保留原设备身份和连接记录，先完全退出应用再备份和迁移。
目录包含敏感连接数据，须私密处理。
两台 Mac 同时使用时，建议新 Mac 注册独立设备身份，避免复制旧身份。

新 Mac 需要重新授予 BilldDesk 录屏和输入控制权限。
安装后通过 Finder、Dock 或 LaunchServices 正常启动应用，授权后完全退出重开。
终端直接运行应用二进制的录屏成功，不能证明 BilldDesk 自身权限有效。
不迁移或直接修改系统权限数据库。
